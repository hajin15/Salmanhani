# 회원 기능 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 이메일·비밀번호 회원가입/로그인/계정관리와, 로그인 사용자의 분석 기록·즐겨찾기.

**Architecture:** `db.py`가 SQLite 연결·스키마·쿼리를, `app.py`가 라우트를 맡는다. 세션은 Flask 기본 `session` 쿠키(`user_id`). 프론트는 `Account.jsx` 하나(로그인/가입 모달 + 내 계정 패널)를 `App.jsx` 헤더에 붙인다.

**Tech Stack:** Flask, 내장 `sqlite3`, `werkzeug.security`, React + Emotion.

**Spec:** `docs/superpowers/specs/2026-11-14-auth-design.md`

## Global Constraints
- 새 의존성 없음 (pip·npm 모두).
- DB 파일 경로: 환경변수 `DB_PATH`, 기본 `salmanhi.db` (프로젝트 루트). `.gitignore`에 `*.db`.
- 비밀번호 8자 이상, 이메일은 간단 정규식 `^[^@\s]+@[^@\s]+\.[^@\s]+$`, 소문자로 저장.
- 에러 응답 형식은 기존과 같이 `{"error": "<한국어 메시지>"}` + 4xx.
- 로그인 안 한 상태에서 `/api/analyze`는 기존과 완전히 동일하게 동작.

## Review Focus
- 같은 이메일 대소문자만 다르게 재가입 → 409 "이미 가입된 이메일이에요." (Task 1 테스트)
- 다른 사용자의 기록 id로 즐겨찾기/삭제 요청 → 404, 상대 기록 변화 없음 (Task 2 테스트)
- 탈퇴 후 기록이 남지 않음 (sqlite는 `PRAGMA foreign_keys=ON`을 연결마다 켜야 CASCADE 동작) (Task 2 테스트)
- 같은 주소 재분석 → 행 1개 유지, 점수 갱신, favorite 유지 (Task 2 테스트)
- 로그인 안 한 채 `/api/history` → 401 (Task 2 테스트)

### Task 1: DB + 회원 API

**Files:**
- Create: `db.py`, `test_auth.py`
- Modify: `app.py` (import·라우트 추가), `.gitignore`

**Interfaces:**
- Produces (`db.py`): `connect() -> sqlite3.Connection` (row_factory=Row, foreign_keys ON), `init()`,
  `create_user(email, password_hash) -> int | None` (중복이면 None), `get_user_by_email(email) -> Row | None`,
  `get_user(user_id) -> Row | None`, `set_password(user_id, password_hash)`, `delete_user(user_id)`.
- Produces (`app.py`): `current_user_id() -> int | None` (세션의 user_id가 실제 존재할 때만).
- 라우트: `POST /api/signup {email,password}` → 201 `{email}` + 로그인 상태,
  `POST /api/login` → `{email}` / 401 "이메일 또는 비밀번호가 맞지 않아요.",
  `POST /api/logout` → `{ok:true}`, `GET /api/me` → `{email}` 또는 `{email:null}`(200),
  `POST /api/password {current,new}` → `{ok:true}` / 401(현재 비번 틀림),
  `DELETE /api/me {password}` → `{ok:true}` + 세션 삭제.

  탈퇴 후 로그인 401.

### Task 2: 분석 기록·즐겨찾기 API

**Files:**
- Modify: `db.py`, `app.py` (`analyze()` 끝, 새 라우트), `test_auth.py`

**Interfaces:**
- Consumes: `connect()`, `current_user_id()`.
- Produces (`db.py`): `save_history(user_id, address, total, grade)` (같은 user+address면 total·grade·created_at 갱신),
  `list_history(user_id, favorite_only=False) -> list[dict]` (최신순, 키: id,address,total,grade,favorite(bool),created_at),
  `set_favorite(user_id, hid, on) -> bool`, `delete_history(user_id, hid) -> bool` (해당 user 것이 아니면 False).
- 스키마: `history`에 `UNIQUE(user_id, address)`.
- 라우트: `GET /api/history[?favorite=1]` → `{items:[...]}` / 401 "로그인이 필요해요.",
  `POST /api/history/<id>/favorite {on}` → `{ok:true}` / 404, `DELETE /api/history/<id>` → `{ok:true}` / 404.
  `analyze()`: 로그인 상태면 응답 직전 `save_history(uid, <응답의 address>, total, grade["grade"])`.

- [ ] **Step 1: 테스트 추가** — 비로그인 `/api/history` 401 / 로그인 후 같은 주소 2번 analyze → items 1개 /
  즐겨찾기 on 후 재분석해도 favorite True / `?favorite=1` 필터 / 다른 사용자가 같은 id 즐겨찾기·삭제 → 404 /
  삭제 후 items 0개 / 탈퇴 후 history 행 0개(db 직접 조회).
- [ ] **Step 2: 실패 확인.**
- [ ] **Step 3: 구현.**
- [ ] **Step 4: `python test_auth.py` → `ok`.**
- [ ] **Step 5: 커밋** `feat: 분석 기록·즐겨찾기 API`
